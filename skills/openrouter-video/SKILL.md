# openrouter-video：这台机器怎么开

本 skill 只讲**机器**：有哪些工具、按什么顺序按、每个参数收什么、哪些动作会花钱、失败了读回执行哪一行。

**创意不在本 skill 的范围。** 分镜怎么写、镜头语言怎么排、一个动作要不要拆两镜，是创意师/导演 agent 的事。
本 skill 的任务是：让导演要得到的东西，机器能接住；并且不在错误的地方花钱。

读完你应该能：不看源码就写出一张合法的图、知道每个回执字段意味着什么、知道失败后按哪个键而不是重跑整片。

## 0. 五个工具：先记住地图

| 工具 | 干什么 | 花钱吗 |
|---|---|---|
| `openrouter_video_plan` | 把一份镜头表**展开成整张图**（节点 + 连线 + 成片节点） | **不花**，只写文档 |
| `openrouter_video_run` | 执行一张图 | **默认 dry-run 不花**；只有 `dry_run:false` 才花 |
| `openrouter_video_status` | 查整图 / 单任务的状态与**实账** | 不花 |
| `openrouter_video_graph` | 操作工作台的手：读图 / 整体写图 / 加节点 / 连线 / 断线 / 删节点 / 删项目 / 列项目 | 不花 |
| `openrouter_generate_video` | 只出**一条**视频（文生 / 首尾帧 / 参考图 / 编辑 / 续接 / 超分） | **花** |

一句话选型：

- **多镜头长片 → `plan` 建图，`run` 执行。** 一个镜头一个 `generate` 节点，一条 `seq` 节点负责拼成片。
- **只改一条、只试一条、只给一条做超分/编辑 → `openrouter_generate_video`**，不必建图。
- **要动图的结构（改连谁、加角色、删镜头）→ `openrouter_video_graph`**，不是重跑 `plan`。

❌ **长片绝对不要用 `openrouter_generate_video` 循环 20 次。** 那样没有续跑、没有预算闸门、没有产物流转；
第 14 条失败时前面的钱白花，而且补不上——因为没有任何文档记录"还差哪几镜"。

## 1. 三条铁律（写在代码里，不是建议）

1. **预检默认开。** `openrouter_video_run({ graph_id })` 永远只预检，报成本上界、不提交任何请求。
   要真跑必须显式写 `dry_run: false`。**每部片子花钱之前，把预检回执给用户看一遍。**
2. **执行可续跑，续跑靠 `only` + `retry_failed`。**
   已经完成的节点不会被重复提交、不会重复计费；失败的节点**默认被跳过**（否则重跑一次图 = 把失败的镜头又付一遍钱），
   要重跑必须显式 `retry_failed: true`。只修了一个镜头就 `only: ["n_s03"]` —— 它跑该节点**及其下游**。
3. **没有取消端点。** 提交即计费、停不下来。`abort: true` 只是"停止派发新节点"，
   **在飞的任务会继续运行并继续计费**。所以"先跑着看看"不是可撤回的动作。

## 2. 标准动作序列

```
1. openrouter_video_graph({ action: "list" })          // 现有项目有哪些，别重复建
2. openrouter_video_plan({ shots: [...], title, cast, scenes, model })   // 不花钱
3. 读回执：graphId / 镜头数 / 上界 / chainedCount / imageBedConfigured / warnings
4. openrouter_video_run({ graph_id })                  // 预检，仍不花钱
5. 把「上界 + 未知量 + 警告」一起报给用户，等确认
6. openrouter_video_run({ graph_id, dry_run: false })  // 到这里才花钱
7. openrouter_video_status({ graph_id })               // 读实账 usage.cost
   ↳ 有失败 → openrouter_video_run({ graph_id, dry_run: false, retry_failed: true })
```

第 3、5 步的每一行都不是仪式：**回执里的 `warnings` 是预检唯一免费的修复机会**，
`imageBedConfigured: false` 意味着接龙会退化成独立生成，`unknownCount > 0` 意味着上界不是上界。

## 3. 工具手册

### 3.0 取值从哪来：模型目录

没有"列出模型"的 agent 工具。你能依靠的是这三条：

1. **给错值会在发请求之前被拒，且消息里直接列出该模型支持的值**（时长 / 分辨率 / 画幅 /
   是否支持首帧 / 是否超分）。把它当查询用：错一次，不花钱，得到一张支持值清单。
2. 工作台的**设置 → 添加模型**输入框带线上目录的自动补全（几百个视频模型），
   这是给人用的；代理要在节点上填 `model` 时，最常见的正确做法是**沿用 `graph.project.model`**，只在其不支持时才换。
3. **目录没加载时，逐模型的本地校验会静默跳过**（`supported_*` 全读不到），
   而且上界算不出来。此时 `run({dry_run:false})` 在超限闸门开着的情况下会**直接拒绝执行**（未发请求）；
   若闸门被关掉，它就会在**没有上界的情况下**开跑。所以预检回执里一旦出现「模型目录没加载成功」，
   先修目录，不要靠"反正有闸门"往下走。

### 3.1 `openrouter_video_plan` —— 建图（免费）

把镜头表展开成：`脚本节点 + N 个 generate 节点 + 取帧节点 + cast/scene/ref 节点 + seq 成片节点`，并连好线。

| 参数 | 说明 |
|---|---|
| `shots[]` | 镜头列表。每条至少 `prompt`。字段见下 |
| `title` | 项目名。`seq` 节点的标题就是导出文件名的主干 |
| `model` / `duration` / `resolution` / `aspect_ratio` | 全片默认值（写进 `graph.project`，节点没单独指定时用） |
| `cast[]` | 角色库：`{name, description, image_url \| image_file}`，建成可复用的 `cast` 节点 |
| `scenes[]` | 场景库：`{name, description, image_url \| image_file}`，建成 `scene` 节点。每一镜用 `shots[].scenes` 声明自己发生在哪个场景 |
| `reference_image_urls[]` | 非角色的风格/产品参考，建成 `ref` 节点**扇出到所有镜头** |
| `chain` | 全片默认衔接。`"frames"`（默认，相邻镜头插取帧节点）/ `"none"`（全部独立起幅） |
| `budget_usd` | 写进 `graph.budget.usd` |
| `generate_audio` | 全片是否生成音频 |
| `script` | 自由文本脚本，存进脚本节点 |

`shots[]` 逐条字段：

| 字段 | 说明 |
|---|---|
| `prompt` | 这一镜的画面与运镜。**导演在这里写事，不写角色长相**（长相属于 `cast`） |
| `endsOn` | 这一镜**留给下一镜的事实**：他做完了什么、什么变了、谁在场、时间推进到哪。**写事实，不写姿势/朝向/机位** |
| `title` | 行名，用在成片顺序表里 |
| `duration` | 这一镜的秒数。**必须在模型的 `supported_durations` 里** |
| `chain` | `"none"` = 这一镜硬切，不接上一镜末帧。不写则跟随全片默认 |
| `cast` | 这一镜出场的角色名。**给了就"替换"默认的"全片所有角色"，不是并集** |
| `scenes` | 这一镜**发生在**的场景名。**给了就"替换"默认的"全片所有场景"，不是并集**；`[]` = 这一镜没有场景（空镜/转场） |
| `link` | `none` / `continue` / `edit`。**本工作区不要用**（见 §9） |

三条容易踩的：

- **两张名单互不干扰，各自只筛自己那一类。** `shots[].cast` 永远不会把地点撤掉，`shots[].scenes` 也永远不会动角色。
  **多地点影片必须按镜声明场景** —— 不声明就是"全片所有场景"扇到每一镜，一条提示词里同时钉着几个互斥的地点，
  三个地点的空镜图也一起发给 provider，模型只能猜。
  **没有任何理由为了多地点把一部片子拆成几个图文档**：一次 `plan` 建全部镜头 + 全部场景 + 逐镜 `scenes` 即可。
- **`endsOn` 是故事连续性的唯一杠杆，接龙不是。** 取帧只把**画面**交过去：一帧图说不出"花瓶已经碎了"、
  "他已经进了屋"。`endsOn` 会被作为**已生成的上一段**插进下一镜提示词开头，并注明**不要重演** ——
  所以它写的是**跨过剪辑仍然成立的事实**，不是上一镜的姿势。
  **硬切换机位、换景别是正常的剪辑**：接不接龙都要写 `endsOn`，但**不要写成"接着上一镜的画面"** ——
  那件事由 `chain` 管；插件对没有接龙的镜头会明确写下"可以换机位、不必接上上一段的画面"。
  留空 = 这一镜什么都不交给下一镜。
- **`image_file` 可以给会话工作目录内的本机文件路径**（例如图像工具刚出的那张图）。
  插件会把它发布到工作台配置的图床，换成 provider 能取的公开 https URL。
  **没配图床会明确拒绝**，不会静默存一个本地路径。
- **`budget_usd` 不是保险丝。** 真正会拒绝派发的是**工作台设置**里的「预算 / 超限即拒」（`budgetUsd` / `abortOnExceed`）。
  图里的 `budget.usd` 目前只是记录与展示。

回执里要看的：`graphId`、`totalSeconds`（**请求值**合计）、`ceilingUsd`（上界）、`unknownCount`、
`chainedCount`、`imageBedConfigured`、`published[]`（本地图发布到图床后的 URL）、`notes[]`、`warnings[]`。

### 3.2 `openrouter_video_run` —— 执行

| 参数 | 说明 |
|---|---|
| `graph_id` | **必填** |
| `dry_run` | 默认 `true`。`true` 只预检 |
| `only` | 只跑这些节点**及其下游**。改一个镜头只重跑它 |
| `retry_failed` | 重跑失败的镜头，已完成的保持不变。默认 `false` |
| `abort` | 停止派发新节点（**不取消在飞任务**） |
| `save_dir` | 保存目录，相对会话工作目录，越界会被拒 |

会因为**前置条件**被拒绝（此时没发出任何请求、没花钱）：没配 API key；模型目录拉不到而超限闸门开着；
`save_dir` 越界；图里有 `error` 级问题（见 §5）。

回执逐块读：

| 回执行 | 含义 |
|---|---|
| `预检通过` + `成本上界` + `另有 N 个节点量级未知` | 上界**不是报价**；未知量不是 0 |
| `注意：` 后面的列表 | 预检的 warnings，**动手前唯一能免费改的机会** |
| `执行结束：完成 X，失败 Y，跳过 Z` | 跳过 = 已完成的没重跑，正常 |
| `实账 $…` | 以 `usage.cost` 为准 |
| `取帧接龙：发布 N 帧` / `失败 N 帧` | 失败帧所在镜头**已经计费**了，但下游拿不到首帧、会退化成独立生成 |
| `成片序列：…（6 镜 · 31.6s · 直接拼接）` | 产物。**`缺 N 镜` 出现时不要当完整片交付** |
| `仍有 N 个镜头处于失败状态` | 要重跑它们必须 `retry_failed: true` |
| `角色库：… 没有接到任何镜头：…` | 没连线的设定对这条片子**完全不起作用** |

### 3.3 `openrouter_video_status` —— 查

- `{ graph_id }`：整图状态 + 逐节点状态与 `$` 实账。
- `{ job_id }`：单任务（配 `wait:false` 的生成调用使用）。

实账一律看 `usage.cost`。预检给的是**上界**，不是报价。

### 3.4 `openrouter_video_graph` —— 操作工作台的手

**它和画布读写同一份图文档**：代理在这里加的节点，就是人刷新后画布上多出来的那个框。

| action | 用途 | 要注意 |
|---|---|---|
| `list` | 列所有项目（id / 标题 / 节点数 / 边数 / 状态） | 做任何事之前先看一眼 |
| `get` | 读整图 | 改图前**必读** |
| `set` | **整图替换**（适合一次性建 20 个镜头） | **会覆盖别人的手笔**；先 `get`，在结果上改 |
| `add_node` | 加一个节点，`node.type` 必填、`node.id` 不能重复 | 半成品图允许缺必填输入，只有环/重复 id 会挡 |
| `connect` | 连一条边 `{from, fromPort, to, toPort}` | 走与画布**同一个校验器**，非法会当场说原因 |
| `disconnect` | 删一条边，用 `edge_id` | — |
| `remove` | 删一个**节点**（连它的边一起删） | 不级联下游；下游会缺输入，由预检点出来 |
| `remove_graph` | 删掉**一整个项目**（不可撤销） | 这是"清空工作台"的正确做法 |

**不要手改 `~/.dsh/openrouter-video/graphs.json`。** 存储层只在启动时 `load()` 一次并常驻内存，
下一次写入会把你手改的内容原样碾回去——看起来像"改了没用"。要走 API。

### 3.5 `openrouter_generate_video` —— 单条

| mode | 需要什么输入 |
|---|---|
| `text` | `prompt`（默认） |
| `first_frame` | `first_frame_url` |
| `first_last` | `first_frame_url` + `last_frame_url` |
| `reference` | `reference_images[]` |
| `edit` | `source_video_url` + `prompt` + 支持编辑的 `model` |
| `extend` | `previous_job_id`（本插件记录过的 id，原样回传） |
| `upscale` | `previous_job_id` 或源视频 + `upscale_factor` 1.5–3 + `creativity` 0/1 |

其余参数：`model` / `duration` / `resolution` / `aspect_ratio` / `generate_audio` / `seed` / `save_dir` / `wait`。
**留空即用工作台默认。** 所有取值都会先对着线上目录做本地校验（时长/分辨率/画幅/是否支持图生视频/是否超分模型），
越界在**发请求之前**就被拒，并列出该模型支持的值。

什么时候用它而不是建图：**只出一条**、给已有的一条做编辑/超分、单独试一个模型的口味。
一旦"这一条将来可能要重跑或被拼进片子"，就该进图。

## 4. 图文档：节点、端口、连线

### 节点类型（14 种，只有 4 种上网）

| type | 中文 | 上网 | 必填输入 | 输出 |
|---|---|---|---|---|
| `script` | 脚本 / 分镜 | | — | `shots`、`brief` |
| `prompt` | 提示词 | | — | `text` |
| `ref` | 参考素材 | | — | `asset`(image[]) |
| `cast` | 角色 | | — | `asset`(image[]) |
| `scene` | 场景 | | — | `asset`(image[]) |
| `generate` | 生成 | ✅ | — | `job` |
| `extend` | 续接 | ✅ | `job` | `job` |
| `edit` | 编辑 | ✅ | `video` | `job` |
| `upscale` | 超分 | ✅ | `job` | `job` |
| `take` | 取帧 | | `job` | `image`(image[]) |
| `seq` | 成片序列 | | — | `manifest` |
| `note` | 注释 | | — | — |
| `group` | 分组 | | — | — |
| `template` | 模板 | | — | — |

`generate` 的三个输入口：`brief`(text)、`frames`(image[])、`refs`(image[])。
> ⚠️ **`brief` 目前没有消费者**：接上去的文字**不会进请求**（实测：`plan` 建的分镜节点连到每一条镜头，
> 而请求体里一个字都没有；一个接了 `brief` 又自己没有提示词的镜头，会带着**空提示词**发出去且**不报任何警告**）。
> 逐镜文案写进那一镜自己的 `prompt`；要交接上一段，用 `endsOn` 或把交接文字写进提示词。
> `plan` 仍会建分镜节点并连线（给人读的分镜稿），但它是**装饰**。

`cast`/`scene`/`ref` 的 `asset` 出线 → 镜头的 `refs`；`take` 的 `image` 出线 → 下一镜的 `frames`。
`seq` 的输入口是 `jobs`（多输入，**可选**）：把镜头接进来就进成片，**接进来的每一镜都按 `shotIndex` 排序**；
`generate`/`extend`/`edit`/`upscale` 的 `job` 出线接 `jobs`。

### 端口收什么（`PORT_ACCEPTS`）

| 输入口 | 接受 |
|---|---|
| `brief` | `text`、`shots` |
| `frames` | `image[]` |
| `refs` | `image[]` |
| `video` | `job`、`video` |
| `job` / `jobs` | `job` |
| `text` | `text` |
| `shots` | `shots` |

### 连线五条规则

1. 端口必须存在，且类型兼容（上表）。
2. **单输入口只收一条边**，再连一条是**替换**不是叠加。`jobs`、`frames`、`refs` 是**多输入口**。
3. 不能成环——执行器只跑 DAG。
4. 同一镜同时接 `frames` 和 `refs` 合法但会警告：provider 拒绝这个组合，插件只发首帧、丢掉参考图。
5. **必填输入空着会挡住执行**（`extend`/`edit`/`upscale`/`take` 的 `job`，`edit` 的 `video`），预检会点名。

> 多输入口这件事值得记住：**在允许多图的 API 上做单输入口，等于静默丢数据。**
> 猫和老鼠同框的镜头，曾经只能带上其中一个。

### 图上的三个全局位

- `graph.project`：`{model, resolution, aspectRatio, duration, generateAudio, seed}`，节点字段为空时的默认值
  （代码里的缺省是 `google/veo-3.1-fast` / `720p` / `16:9` / `8s` / 有声；新建图时会用**工作台设置**里的对应值覆盖）。
  **优先级：节点字段 > `graph.project`。**
- `graph.budget`：`{usd, onExceed}`。记录与展示用，**不构成闸门**。
- `shotIndex`（节点级）：镜头在成片里的位置。`seq` 节点按它排序拼接；重复的 `shotIndex` 会警告。
  只有 `generate` / `extend` / `edit` / `upscale` 能带 `shotIndex`。

## 5. 预检会说什么（照这张表改，不要重跑整片）

**error（挡住执行）：**

| code | 人话 | 怎么修 |
|---|---|---|
| `empty` | 图里没节点 | — |
| `dup-id` / `bad-type` | 节点 id 重复 / 类型不认识 | 删重复的；未知类型**不会被改写**，只会被拒绝 |
| `missing-required` | 必填输入没接 | 补一条线 |
| `cycle` | 有环 | 断掉回边 |
| `no-model` | 没指定模型 | 节点或 `graph.project` 里补 |
| `unknown-model` | 模型不在线上目录 | 换模型或刷新目录 |
| `bad-duration` / `bad-resolution` | 模型不支持这个时长/分辨率 | 消息里直接列了支持值 |
| `mode-unsupported` | 这个模型不能做首帧图生视频 | 换模型；接 `frames` 之前先看 `supported_frame_images` |
| `not-upscaler` | 这个模型不是超分模型 | 换 `model` |

**warning（不挡，但都要读）：**

| code | 人话 |
|---|---|
| `frames-over-refs` | 同镜接了 frames 和 refs：provider 会拒绝，插件只发首帧、丢掉参考图 |
| `cast-overridden-by-frames` | 同上，而且这个镜头**确实带了角色/场景设定**，那些参考图会被丢 |
| `frame-chaining-needs-imagebed` | 取帧链不会生效：没配图床，抽出的帧没有公开 URL |
| `cast-without-description` / `scene-without-description` | 只给了参考图、没写固定描述：提示词仍会各写一遍，每镜都会漂 |
| `cast-unused` / `scene-unused` | 设定没连到任何镜头，对这条片子**完全不起作用** |
| `dup-shot` | 两个镜头占了同一个 `shotIndex` |
| `model-switch` | 相邻两镜换了模型且没有续接关系，会有观感与编码断层 |
| `no-handoff` | **全片没有一个镜头写 `endsOn`**：跨过接缝没有任何故事交接。接龙只传画面，硬切连画面都不传。确实该逐镜独立的片子可以忽略 |

## 6. 工作台：人和代理各用哪只手

**同一份图文档，两个入口。** 人点按钮、代理调 `action`，落到同一个 `graphs.json`。
所以：代理改完图，人如果没看到变化，让他点右上「刷新」或切一次项目——
**画布在执行中每 4 秒自拉一次快照，空闲时不拉。**

| 人看到的 | 作用 | 代理这边的等价动作 |
|---|---|---|
| 顶栏标题（`▾`） | 项目列表：切换 / 新建 / 删除 | `list` / `set` / `remove_graph` |
| 顶栏「设置」 | OpenRouter 密钥；模型短名单（含「设为默认」）；图床地址/文件夹/User-Agent/令牌 +「测试连通」 | 代理**不改**设置。要改一条镜头的时长/分辨率/画幅/音频，改**那个节点的字段** |
| 顶栏图床一行 | 图床**配了没**（一个灯 + 已配置/未配置，不给地址；未配置会明说接龙不生效）；点开进设置 | 取帧接龙的**前提条件** |
| 顶栏「密钥」一行 | 密钥**配了没**（一个灯 + 已配置/未配置，不给任何一段密钥）；点开进设置 | 生成能否成功的前提 |
| 底部缩略图条 | 每一镜一格；已经有片子的格子点开在弹框里播，并列出该镜时长/模型/实账/衔接 | 看 `run`/`status` 回执的逐镜行 |
| 节点卡片 / 检查器里的图 | 跑完的镜头显示视频；角色/场景/参考素材节点显示参考图；检查器第一张卡片有一行「这个节点是干什么的」 | — |
| 顶栏「设定」/「设定库」 | 角色与场景：名称、固定描述、参考图、接到哪些镜头 | `plan` 的 `cast`/`scenes`，或 `add_node` + `connect` |
| 「预检」按钮 | 同上，人手动跑 dry-run | `run`（默认就是预检） |
| 「▶ 运行这一镜及下游」 | 跑选中节点**及其全部下游**（Host 把 `only` 展开成传递闭包）；已完成的跳过 | `run` 的 `only: [节点]` |
| 「↻ 重跑失败的 N 镜」 | 只在选中范围内有失败镜头时出现；重新提交那些失败的镜头，**会再次产生费用** | `run` 的 `only: [节点], retry_failed: true` |
| 成片面板 | 成片是否已导出、是否**不完整**（缺哪几镜） | `run` 回执里的 `成片序列` 行 |
| 双击节点标题 / 检查器「重命名」 | 改名。改 `seq` 名 = 改成片文件名 | `set`（改 `title`） |
| 检查器「删除节点」/ `Delete` 键 | 删节点，先弹确认写明影响几条线 | `remove` |
| 检查器「从这个镜头撤下」 | 把某个角色撤出某一镜 | `disconnect` 那条边 |
| 「刷新」 | 重新拉快照 | — |

三条关于"别把人搞糊涂"的常识：

- **授权边界：代理不碰密钥。** 需要密钥就在回执里说"去顶栏设置里填"，不要尝试读或写它。
- **删项目 ≠ 退钱、≠ 删文件。** 删的只是图文档（意图）；台账和已生成的 mp4（事实）都还在。
- **删节点不级联下游**，这是故意的：一次点击删掉一条付费链是不可接受的。下游缺输入由预检点名。
- **人一直在看着你的运行。** 工作台空闲时每 10 秒、有运行在跑时每 4 秒读一次快照，
  所以 agent 起的运行会**实时**出现在人的画布上（节点变黄、缩略图条出现 `◌`、跑完一镜当场出预览）。
  不要在回执里写"你可以点刷新看看" —— 他不用点。

## 7. 花钱的规矩

- **预检给的是上界，不是报价。** `usage.cost` 才是实账。
- **`unknownCount > 0` 时上界不完整**（按 token 计价的模型没有可用的每秒 SKU）。量级未知 **≠ 0**。
- **参考图可能换一档更贵的 SKU。** 目录里带 `reference_*` 单价的模型（如 `heygen/heygen-video-1`）
  在带参考图时贵一倍（768p 无声 $0.03/s → 带参考 $0.06/s）。
- 单条 8 秒镜头的量级（用于心算，不是报价）：

| 档 | 模型 | 一条 8s |
|---|---|---|
| 便宜 | heygen-video-1 480p | ~$0.16 |
| 常用 | veo-3.1-fast 720p 带音频 | ~$0.96 |
| 贵 | sora-2-pro 720p | ~$2.40 |
| 最贵 | veo-3.1 720p 带音频 | ~$3.20 |

- **三分钟片子按 8 秒一镜 = 23 条**，常用档约 $22，最贵档约 $74。报预算时把条数说清楚。
- **修一条比重生成一条便宜得多。** 「先出粗剪 → 只对不合格的镜头逐条 `edit`」远比"不满意就整条重来"划算。

## 8. 排障：读回执，别重跑整片

| 现象 | 根因 | 动作 |
|---|---|---|
| 一镜 `failed`，错误含 `does not accept input_references alongside a first_frame image` | 该镜同时接了 frames 和 refs | 现行插件会自己丢掉 refs、只发首帧；**若仍看到这条 400，说明跑的是旧版 Host**（改动在 Host 半边，Host 不热重载，要重启 DSH） |
| 接龙镜头退化成独立生成 | 没配图床，或图床 403（Cloudflare + 错的 User-Agent） | 先在设置里点「测试连通」，别等到三镜之后 |
| 回执说 `缺 N 镜` | 有镜头没成功 | **不要当完整片交付**；补跑失败镜，成片会自动重切 |
| 成片回执说 `磁盘上已有，未重切`，但镜头集合其实变了 | 缓存判据 | 现在的判据是"镜头集合与上次一致"，集合变了必重切；若仍命中，删掉该 mp4 再 `only: [seq节点]` |
| `仍有 N 个镜头处于失败状态` | 失败的默认被跳过 | `retry_failed: true` |
| `费用：尚未回填` | 任务还没终态 | 稍后 `status({job_id})` |
| `模型不在线上目录里` | 模型 id 错，或目录过期 | 核对 id / 刷新目录 |
| 目录没加载 → 上界算不出来 | 网络 | **上界未知不等于免费**，先修目录再执行 |

## 9. 实测事实（别再重新论证，也别反着用）

| 事实 | 结论 |
|---|---|
| 一次 API 调用只出 **1 条**片段（约 5–15 秒） | 长片 = N 条拼起来，费用是 N 倍 |
| heygen 请求 5s，实际每镜 **5.258s** | 预检的"总时长"是**请求值**合计；交付时长看 `seq` 回执的 `durationSec`（ffprobe 实测） |
| `frame_images` 与 `input_references` **互斥**：同发是 **400，整镜失败** | 不是"以首帧为准"的软优先级。插件丢 refs、只发首帧 |
| 参考图真正生效在**硬切**镜头（`chain: "none"`） | 接了首帧的镜头拿不到参考图 |
| 取帧接龙有效（12 镜实测，同片对照） | 接缝 SSIM 均值 **0.902** / 最差 **0.852**；同片无接龙版均值 0.394、最差 0.032 |
| 但接龙不是万能的（30s 6 镜实测） | 把「大全景缓推」接给「中景横移」，接缝 SSIM 只有 **0.654**（该片无接龙对照 0.394）→ **要接在景别接近的两镜之间**，否则首帧约束和提示词里的运镜会互相拉扯 |
| 取帧本身**不花钱**（本地 ffmpeg + 图床上传） | 没有理由为省钱关掉它 |
| `link: "continue"`（`previous_job_id`）在本工作区**不可用** | 唯一给它定价的模型被 guardrail 挡，seedance 回 400。不要为了连续性去开它 |
| 实账每镜按"不带参考图"那一档计费，画面里角色却是稳的 | **"参考图有没有被采纳"尚未验证**；确定生效的是 `cast`/`scene` 里那段**固定描述**，而且免费 |
| 固定描述会被**原样插进**每条出场镜头的提示词开头 | 写**外形/地点/光线/材质**，不写动作与情绪 |
| `brief` 输入口**没有消费者**（实测） | `plan` 建的分镜节点连到每一条镜头，请求体里却一个字都没有；手接的 `prompt` 节点也进不去。可见"有端口、有连线、有文档"不等于有实现 |
| `endsOn` 到达请求体（实测） | 只来自**上一镜**、按 `shotIndex` 顺序、只出现一次、`[]`/留空则什么都没有；标记是幂等键，手写的块不会被重复插入 |
| 故事连续性**没有**被模型层面的效果验证过 | 确定性的一半（文本进到请求、顺序正确、幂等）是证过的；"模型听不听"没有实测。要断言效果，先做付费 A/B |

## 10. 不要做这些

- ❌ 用 `openrouter_generate_video` 循环做长片。要长片就建图。
- ❌ `action: "set"` 覆盖整图而不先 `get` —— 你会把别人的手笔一起抹掉。
- ❌ 手改 `graphs.json`。内存常驻，下一次写入就把你改的碾回去。
- ❌ 同一镜接 `frames` 又接 `refs`，然后期待参考图生效。**那是 400，不是覆盖。**
- ❌ 用 `link: "continue"` 求连续性。本工作区这条路是死的，用取帧接龙。
- ❌ **以为接龙就等于故事连续。** 取帧交的是**画面**（接缝 SSIM 0.902），交不了"他刚才把花瓶踢倒了"。
  故事靠 `endsOn` —— 而且**硬切镜头**（`chain: "none"`）里它是唯一能过到下一镜的东西。
- ❌ **把 `endsOn` 写成上一镜的姿势/朝向/机位。** 硬切换机位、换景别是正常剪辑，
  写成"从上一镜的末帧继续"会让这条文字变成第二个接龙机制，还会和剪辑意图打架。
- ❌ 把整段上一镜的提示词复制到下一镜。视频模型会照着提示词演，于是下一镜开头把上一镜**又演一遍**；
  要过去的是"已经发生的事实"，不是上一镜的全文。
- ❌ 加了 `cast`/`scene` 节点却不连到镜头。**没连线的设定完全不起作用**，只是画布上一个好看的框。
- ❌ 把基础设定写进每一条 `shots[].prompt`。角色长相写进 `cast`、地点写进 `scene`，
  每镜各写一遍正是"每一镜的角色都不一样"的成因。
- ❌ 删节点、删项目，以为能退钱。退不了，也删不掉台账和已下载的文件。
- ❌ 让**一个节点**既出画面又出演员表——`seq` 负责拼，`take` 负责取帧，各管一件事。
